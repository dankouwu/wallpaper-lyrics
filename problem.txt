I am building an Android application called Wallpaper Lyrics using Kotlin. It renders time-synced lyrics on the phone's wallpaper canvas.

# The Bug
The lyrics highlighting is jumping in discrete chunks. It visually highlights a group of words instantly, then waits for the audio to catch up. This is happening because the UI render loop is tied directly to Android's `MediaController` or `MediaSession` playback state updates, which only fire periodically (e.g., every 500ms to 1000ms).

# The Task
Write the Kotlin implementation to fix this using "playback position extrapolation" so the renderer operates smoothly between system updates.

### Requirements:
1. **State Management:** Create variables to store the `lastKnownPlaybackPosition` (the raw position from the OS) and the `lastUpdateTime` (using `SystemClock.elapsedRealtime()`) whenever a system media update is received.
2. **Extrapolation Logic:** Write a function `getExtrapolatedPosition(): Long` that calculates the exact current millisecond position. It must calculate the time elapsed since `lastUpdateTime` and add it to the `lastKnownPlaybackPosition` (accounting for whether the track is currently playing or paused).
3. **Smooth Render Loop:** Provide a structural example of a continuous render loop (e.g., using `Choreographer.FrameCallback` or a coroutine loop calling `invalidate()`) that fetches the `getExtrapolatedPosition()` every frame to drive the word-by-word visual highlighting smoothly.
